# Scarab Modern 2.8.4 — Unity 6 / API v78

Форк настоящего [fifty-six/Scarab](https://github.com/fifty-six/Scarab), с подключёнными
исходниками разрабатываемого Modding API v78 для **Hollow Knight 1.5.12620**.
Основа менеджера: `15d350573a660c6fceb40d80218dd09b606d4ea9`.

**Неофициальный форк Scarab.** Авторы менеджера — fifty-six и участники Scarab.
Новый Modding API взят из [hk-modding/api PR #164](https://github.com/hk-modding/api/pull/164)
и [исправлений SFGrenade/api PR #5](https://github.com/SFGrenade/api/pull/5);
авторство API и этих портов принадлежит их разработчикам. Точные commit и лицензии сохранены в
[vendor/api-provenance.json](vendor/api-provenance.json) и `vendor/api`.

**Проверено 18.10.2026 на Windows Steam: Hollow Knight 1.5.12620, Unity 6000.0.61f1, API v78, DebugMod 1.4.10.2.**
Готовая сборка: `out/win-x64/Scarab.exe` (переносить всю папку).
Совместимость остальных старых модов и других платформ требует отдельных игровых проверок.

## Исправление сборки API 2.8.3

Сборка API в AppData теперь использует строго установленный стабильный SDK 8.0.
SDK 10 больше не выбирается автоматически. Если SDK 8 отсутствует, установите
[.NET 8 SDK x64](https://dotnet.microsoft.com/download/dotnet/8.0) и перезапустите менеджер.
Сервер компиляции отключён, вывод инструментов сохраняется в UTF-8.

## Исправление упаковки 2.8.2

Архив 2.8.1 ошибочно не включал часть неизменённых файлов. В 2.8.2 восстановлен полный

## Обновление 2.8.1

Исправлены версии с `.0`, определение версии игры, загрузка файлов, запись DLL без лишних байтов,
циклические/отсутствующие зависимости и восстановление после неудачной установки/удаления мода.
Добавлены проверка SDK и доступа на запись, потоковый лог сборки API и постоянное окно ошибок.
Полный список: [CHANGELOG-modern.md](CHANGELOG-modern.md).

При ошибке отчёт автоматически сохраняется в `%APPDATA%\HKModInstaller\Logs\error-*.txt`
на Windows. В окне ошибки можно выделять текст, копировать его или сохранять `.txt` в выбранную папку.
В Settings есть отдельная кнопка диагностики. Отчёт включает полный exception, ОС, версию среды,
папку/версию игры и последние части логов; целые DLL и сохранения в него не включаются.
Автоматические отчёты и временные сборки не отправляются никому.

Чтобы обновиться, распакуйте исходники в новую папку и запустите `Start-Windows.cmd` для пересборки.
Старый ярлык на EXE из другой папки сам не обновляется. Новый заголовок окна содержит **2.8.4**.
Существующие моды/настройки не удаляйте; совместимые проверенные квитанции API v78 используются повторно.

## Исправления поверх этих веток

* Preloader сохраняет прежнее состояние `AudioListener.pause` и восстанавливает его в `finally`
  при завершении/Dispose итератора. Раньше ранний выход мог оставить аудио выключенным.
* Ошибки архитектуры нативной библиотеки и отсутствующего entrypoint при Prelink
  теперь, как и отсутствие DLL, выбирают FullScene preload.
* PrePatcher и PostPatcher завершаются с кодом 2 при неверных аргументах, а не сообщают успех.
* Очистка старых `MONOMODDED_*` файлов использует `$(TargetDir)`, совпадая с рабочей папкой патчера.
* Добавлен независимый regression fixture для PreventInline: NoInlining установлен,
  AggressiveInlining снят. Он дополняет взятые из PR тесты HookGen.

Регрессионный HookGen.exe собран и выполнен: проверки перенаправления типов, старых сигнатур и хуков проходят.

## Как API встроен в менеджер

Для **1.5.12620** первая установка API автоматически:

1. Определяет версию через `globalgamemanagers` и метаданные DLL; если Unity-строка недоступна,
   использует чистую `Constants.GAME_VERSION`. Нулевой четвёртый компонент нормализуется.
2. Распаковывает закреплённые исходники в отдельную рабочую папку.
3. Копирует DLL собственной игры в `Vanilla`. При переустановке берёт проверенные оригиналы
   из предыдущей квитанции. Файлы игры не загружаются со сторонних сайтов.
4. Запускает `dotnet build` для платформы выбранной игры, включая Windows/Proton.
5. Проверяет номер игры и наличие `Modding.ModHooks` в получившейся сборке.
6. Устанавливает весь `OutputFinal` с резервными копиями и откатом при ошибке записи/сохранения состояния.

Исходники закреплены по commit, а не скачиваются с движущейся ветки при каждом запуске.
Встроенный API не выдаётся за официальный стабильный релиз.

**API v78 меняет несколько файлов.** Переключение в vanilla восстанавливает
`Assembly-CSharp.dll`, `TeamCherry.Localization.dll` и все остальные заменённые файлы,
удаляет добавленные зависимости. Включение возвращает полный проверенный API-пакет.
Файлы кэша проверяются по SHA-256; несовпадение версии/содержимого блокирует переключение.

Для **1.5.78.11833** сохраняется официальный канал: ApiLinks/GitHub Releases, SHA-256,
проверка реальной версии DLL внутри архива. Если ApiLinks не подходит, ищутся до 100 релизов.
Встроенный v78 не устанавливается на **1.5.12459** или любую другую сборку.
Он нацелен строго на **1.5.12620**; соседние номера нельзя объявлять совместимыми без проверки.

## Сборка менеджера

Нужны .NET **8 SDK** и интернет для NuGet. Исходники API уже включены.

Windows: запустите `Start-Windows.cmd` (сборка, проверки и запуск), либо вручную:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1
```

Результат: `out/win-x64/Scarab.exe` и файлы рядом. Переносите всю папку.

Linux/macOS:

```bash
./scripts/build.sh linux-x64
# либо osx-arm64 / osx-x64 для самого менеджера
```

## Первый запуск API v78

1. При переходе с обычного Scarab сначала восстановите файлы игры в Steam/GOG.
   Непроверенные старые `.v`/`.m` не используются в качестве оригинальных DLL.
2. Запустите менеджер, укажите игру **1.5.12620**. Закройте саму игру.
3. Нажмите Install API. Первый запуск собирает API; это может занять несколько минут.
   После успешной установки последующие переключения не требуют пересборки.
4. Установите нужные моды. Старые моды могут потребовать адаптации к Unity 6.

Для **первой сборки API** нужен доступный через PATH .NET SDK 8.0.
На Linux/macOS также нужен **Mono**, поскольку инструменты патчинга работают на net472.
На macOS нужен **lipo** из Command Line Tools; API собирается как osx-x64 с universal native dylibs,
чтобы работать в arm64 и Rosetta-процессах игры. Это поведение взято из PR #5.
Дополнительно здесь выполнен запуск Windows Steam 1.5.12620 с API v78 и DebugMod 1.4.10.2.

Менеджер блокирует изменение API/модов, если обнаруживает запущенный процесс Hollow Knight.
Перед установкой проверяются права записи. Моды устанавливаются через временную папку с откатом;
пользовательские файлы, не принадлежащие предыдущему установленному пакету, сохраняются.
Старые установки Scarab без списка файлов считаются пользовательскими: их неизвестные файлы
не удаляются автоматически при обновлении.

Логи локальной сборки API: `HKModInstaller/Logs/api-build-*.txt`
в системной папке данных приложений. Они пишутся по мере выполнения restore/build,
включая ошибки и таймауты. Отчёт можно открыть через Settings → «Диагностика / сохранить лог .txt». Рабочие папки сборок сохраняются для диагностики,
содержат ваши скопированные DLL и могут занимать значительное место.

Кэш API: `Managed/.scarab-api/<id>`, квитанция: `Managed/.scarab-api.json`.
Резервные копии каждой операции: `Managed/.scarab-backups/<id>/recovery.json` и соседние файлы.
Не удаляйте кэш, пока используете переключение API. Откат защищает от исключений;
атомарность при отключении питания или принудительном завершении процесса не гарантируется.

Настройки и список модов общие с оригинальным Scarab (`HKModInstaller`). Не запускайте оба одновременно.
API-пакеты старой версии этого форка без новой многофайловой квитанции требуют восстановления игры.

## Если видно только «Определение проектов для восстановления…»

Это восстановление NuGet-пакетов, ещё до компиляции. В этой версии удалены лишние
Avalonia Nightly/MyGet источники; используются nuget.org, отдельные restore-шаги
с подробностью normal и номера этапов 1/7–7/7. Последующие test/build/publish
запускаются с --no-restore. При первом запуске загрузка может занять несколько минут.
Повторяющиеся Retry, NU1301, TLS или DNS ошибки указывают на проблему доступа к источнику;
сохраните полный текст ошибки. Точную причину задержки нельзя установить по одной строке.
